# project-kickoff

## When to use

Use at the start of a project or substantial workstream.

## Workflow

1. Define problem, users, outcomes, scope, non-goals, stakeholders, and constraints.
2. Choose milestones around demonstrable outcomes.
3. Surface major assumptions, dependencies, and risks early.

## Output contract

A kickoff brief that aligns execution and evaluation.

## Guardrails

- Load this skill only when it materially improves the task.
- Prefer concrete evidence over assumptions.
- Keep the result proportional to the user's requested depth.
- Do not repeat context that is already available unless it is needed for the output.
