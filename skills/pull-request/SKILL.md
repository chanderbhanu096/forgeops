# pull-request

## When to use

Use when a branch is ready for collaborative review.

## Workflow

1. Summarize what changed, why, impact, and notable tradeoffs.
2. Include testing evidence, risks, rollout, and examples when relevant.
3. Keep unrelated work out of the pull request.

## Output contract

A review-ready pull request title and description.

## Guardrails

- Load this skill only when it materially improves the task.
- Prefer concrete evidence over assumptions.
- Keep the result proportional to the user's requested depth.
- Do not repeat context that is already available unless it is needed for the output.
