# stop-condition

## When to use

Use when research, debugging, brainstorming, or iteration could continue indefinitely.

## Workflow

1. Define success, failure, and escalation criteria before deep iteration.
2. Stop when the decision would not materially change with more work.
3. Record remaining uncertainty instead of hiding it.

## Output contract

Explicit stop criteria and unresolved uncertainty.

## Guardrails

- Load this skill only when it materially improves the task.
- Prefer concrete evidence over assumptions.
- Keep the result proportional to the user's requested depth.
- Do not repeat context that is already available unless it is needed for the output.
