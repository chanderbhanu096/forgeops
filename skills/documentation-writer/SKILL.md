# documentation-writer

## When to use

Use for READMEs, runbooks, setup guides, API docs, or internal guidance.

## Workflow

1. Identify the reader and task.
2. Verify commands, prerequisites, defaults, and failure cases against reality.
3. Prefer examples and task-oriented structure over feature marketing.

## Output contract

Concise documentation tied to actual behavior.

## Guardrails

- Load this skill only when it materially improves the task.
- Prefer concrete evidence over assumptions.
- Keep the result proportional to the user's requested depth.
- Do not repeat context that is already available unless it is needed for the output.
