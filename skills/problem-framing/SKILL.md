# problem-framing

## When to use

Use when people are solving symptoms, mixing problems, or lacking a clear outcome.

## Workflow

1. Separate current state, desired state, gap, affected users, and constraints.
2. Distinguish symptoms from likely causes.
3. Define measurable success and explicit non-goals.

## Output contract

A concise problem statement with success criteria.

## Guardrails

- Load this skill only when it materially improves the task.
- Prefer concrete evidence over assumptions.
- Keep the result proportional to the user's requested depth.
- Do not repeat context that is already available unless it is needed for the output.
