# retrospective

## When to use

Use after projects, releases, incidents, experiments, or repeated workflows.

## Workflow

1. Separate outcomes from process observations.
2. Identify what helped, what hurt, and why.
3. Convert lessons into a small number of owned, measurable changes.

## Output contract

A concise retrospective with concrete follow-ups.

## Guardrails

- Load this skill only when it materially improves the task.
- Prefer concrete evidence over assumptions.
- Keep the result proportional to the user's requested depth.
- Do not repeat context that is already available unless it is needed for the output.
